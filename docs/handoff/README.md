# 流水分析项目 · 公司系统接入需求包

版本：v1.0 评审稿｜日期：2026-09-29｜用途：开发评审、估时、联调与验收。

## 给开发的任务说明

将现有微信、支付宝流水分析原型产品化，接入公司业务系统。公司业务单发起资料采集，客户通过 H5 上传流水，服务端异步解析、核验身份、按人合并，原文件进入公司私有文件存储，结构化结果进入公司数据库；审核人员从公司平台查看报告、下钻明细、处理补件和异常。

**用户已确认：H5 仅用于客户上传流水；本期不开发客户查看报告或审核人员手机看报告的独立 H5。** 报告保持当前审核版内容及主要交互，不进行大幅视觉重做。

公司技术栈、身份接口、数据库、部署资源、业务量尚未提供。本文给出可评审方案和建议初值，不代表已与公司确认，也不代表生产服务已经实现。开发应先关闭本文“开工前确认”项，再锁定排期。

## 一期交付边界

1. 业务单关联、公司身份与权限接入。
2. 客户采集 H5、授权记录、双平台文件提交、补件。
3. 文件安全接收、ZIP 解密解压、既有版式解析、校验、身份核对。
4. 异步任务、规则分析、同人双平台报告、版本与来源追溯。
5. 公司数据库和私有对象存储，PC 审核平台及业务系统入口。
6. 通知回调、失败重试、操作审计、保留与删除策略、部署和恢复手册。

OCR、银行流水、通用 XLS/支付宝 Excel、新信用评分模型、自动审批、跨平台转账自动抵扣、对外报告分享、全量导出不列入一期默认范围。单个平台先出报告属于显式例外流程，默认需微信和支付宝材料齐备。

## 开工前最重要的确认

| 决策 | 本稿建议 | 公司确认方 |
| --- | --- | --- |
| 接入方式 | 公司后端管理业务，独立 Python Worker 解析；复用公司队列与存储 | 技术负责人 |
| 系统主键 | 公司提供稳定的客户 ID、业务单 ID、组织 ID，姓名不能当主键 | 业务系统负责人 |
| 报告用途 | 作为审核材料，不自动输出授信/审批结论 | 业务负责人 |
| 身份核验 | 与公司客户身份比对；不一致阻断，无证件材料人工确认 | 业务/安全负责人 |
| 存储和保留 | 公司数据库 + 私有对象存储；保留期限和删除流程上线前确定 | DBA/安全/业务 |
| 技术与容量 | 沿用公司技术栈；实测后定资源，不把建议性能当已达成 | 技术/运维 |

更多决策及责任划分见 [06](06-delivery-acceptance.md)。
