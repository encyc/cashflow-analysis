# 02 · 产品需求

状态：开发评审稿。标记 P0 为一期上线必需，P1 为后续可选。H5 仅用于客户采集，审核报告通过公司 PC 平台查看。

## 1. 用户与权限

| 角色 | 允许操作 | 默认不可操作 |
| --- | --- | --- |
| 客户 | 通过绑定业务单的采集会话上传、补密码、查看本人提交状态 | 查看报告、他人材料、修改业务单归属 |
| 业务经办 | 对获授权业务单发起采集、查看齐备/缺件状态、催补材料 | 无权限时查看完整交易明细或下载原件 |
| 审核人员 | 查看所分配业务单的报告、筛选/下钻、填写审核备注、申请补件 | 修改原始流水、将场景命中自动写成审批结论 |
| 审核主管 | 处理身份疑点和单平台例外、锁定审核采用版本 | 越组织访问、覆盖历史版本 |
| 运维/管理员 | 任务重试、配置和运行状态管理 | 仅凭管理员身份默认获得全部客户流水 |

公司现有 SSO/RBAC 继续使用；业务单、组织、归属范围在每次数据访问时由服务端校验。下载原件、人工确认身份、删除、规则发布分别设权。所有敏感操作记录审计。

## 2. 主流程（P0）

1. 经办在公司业务单点击“采集流水”，创建采集单，绑定 `org_id + business_id + subject_id`。系统默认要求微信与支付宝各一份；申请单定义期望账单期间。
2. 系统生成有期限、可撤销的客户采集链接，由公司现有渠道交付客户。链接不含姓名、手机号、证件号，不作为报告访问凭据。
3. 客户确认机构、用途、授权版本，完成公司认可的身份校验后上传文件；分别显示两平台材料进度。
4. 文件落私有存储并生成持久化任务后显示“已收到，正在处理”。上传完成进度与解析完成进度明确区分。
5. 服务端进行内容检测、解密解压、解析、数据核对和身份匹配；错误给出可补救原因。
6. 所需平台齐备且身份通过后自动生成同人合并报告，保存新版本并通知业务系统。
7. 审核从业务单或报告列表打开报告，下钻到原始记录；采用的报告版本锁定在审核记录中。
8. 补件产生新输入集合和新报告版本。既有成功版本继续可读，待最新成功版本发布后展示“有新版本”，不静默改变已采用报告。

业务单绑定客户，报告属于“该业务单的一次材料集合”，不是将该客户所有历史业务流水永久混在一起。不同业务单即便同一人也不自动复用原件，复用需另行授权与来源记录。

## 3. PC 审核平台（P0）

### P-01 报告/采集列表

字段：业务单号、审核对象（按公司脱敏规则）、所属组织/经办、要求的平台、材料状态、任务状态、最近提交时间、最新报告版本、异常摘要。

支持按业务单号、客户授权范围内的检索条件、平台齐备情况、状态、日期筛选和分页；排序稳定。入口：发起采集、查看材料、查看报告、补件、查看历史版本。无权限行不出现在列表，接口同样拦截。

### P-02 资料与处理详情

显示每份材料的平台、文件类型、声明账单期间、上传时间、处理状态、身份比对结果和补件原因。核验技术明细只放有权限的后台诊断抽屉，不恢复到审核报告正文。

同一平台存在多份材料时，明确“当前选用/被替换/未采用”。一期每次报告最多选用每个平台一份文件，减少跨期重叠重复统计；ZIP 只允许一个有效账单文件加无关说明文件。多账单 ZIP 提示分别上传或重新导出，不自动混合。

操作：重新邀请、撤销采集链接、补密码、重新上传替换、重试可恢复任务、人工确认无证件材料、单平台例外。每项显示权限与结果；无证件材料确认需要理由和公司身份核验记录。明确证件冲突必须更正材料/归属，不能靠“忽略错误”合并。

### P-03 报告详情

标题固定“个人流水分析报告”；头部保留审核对象、账单期间、报告版本和材料完整性提示。报告主体不再增加“数据核验与解读”“平台与来源覆盖”模块。

| 模块 | 一期保留内容与交互 |
| --- | --- |
| 场景识别 | 租赁、网贷及信用往来、回收，时间/平台筛选及对应流水 |
| 整体交易 | 笔数折线、收入/支出柱状，双轴说明；点击月份下钻 |
| 租赁 | 每渠道独立明细、分页、事件类型；待核渠道有明确文字 |
| 网贷及信用往来 | 账单截止日锚定的 7/15/30/90/180 天及全量聚合；区分还款、营销、其他 |
| 回收及二手平台 | 按渠道展示收支与流水，不能直接推断套现 |
| 交易画像/标签 | 描述性分类与命中依据，下钻原流水；多标签可重叠 |
| 收支趋势、分类、交易对手 | 保留原型主要图表、排行、筛选 |
| 付款方式与银行卡 | 依原账单展示及分组，卡信息脱敏，不推断欠款 |
| 明细查询 | 平台、方向、分类、场景、关键词、日期、金额，服务端分页 |
| 报告说明 | 简明说明金额、退款、中性交易和识别依据 |

场景筛选沿用现有交互，不声称一个筛选器控制所有模块。网贷周期固定截止日窗口仅受平台选择影响；自定义日期控制场景、渠道、整体交易，界面就近说明范围；旧图表有各自口径。前后端共用 04 的统计契约，不能各自算一份。

详情返回具体源文件、页/行定位；只有原件权限者能打开受控原件预览。审核备注与原数据分开保存。未命中显示“未识别到相关交易”；字段缺失显示“未提供”；未收到某平台显示“未提供该平台”，均不能当作 0。

### P-04 状态与版本

展示“待上传、处理中、待补件、可审核、处理失败、已关闭”。最近尝试失败与已有可用报告分别展示。例如“已有 V1；V2 生成失败”，不能把整个业务单显示成无报告。旧版本标明历史，审核采用版本保持不变；删除后不给出可访问旧链接。

## 4. 客户采集 H5（P0）

### H-01 进入与授权

使用短期一次性交换码换取采集会话，服务端绑定客户与业务单。链接泄露后仍须完成公司认可的短信验证或登录；不能把填写姓名视为身份核验。建议链接有效期 24 小时，会话闲置 30 分钟失效，可重发，最终由公司确认。

展示公司真实名称、用途、采集数据范围、联系方式和保存规则。勾选默认关闭。服务端保存授权版本/文本摘要、同意时间、主体、会话和撤回记录；没有有效授权不受理文件。具体授权文本由公司确认。

### H-02 导出与上传

两平台分别引导，前后返回保留已填内容，不重新传输已收文件。页面列明支持的具体格式，而不是仅写“支持 PDF/Excel”。上线前用当时微信、支付宝客户端核对导出路径。

一期目标支持现有版式 PDF、微信 XLSX，以及含这些格式的受支持加密 ZIP。未加密文件不强制填密码；服务端检测到加密再提示补充。仅收文件解压/打开密码，不收微信支付宝登录密码、支付密码。

显示文件名、大小、所选平台、上传进度、取消/重试。建议单文件上限 100 MiB，最终与网关、API、存储保持一致。MIME/扩展名/文件内容不符须拒绝；不能信任客户选择的平台，应由解析确认。

### H-03 成功和补件

成功文案“文件已收到，正在处理”，展示随机提交编号和两平台进度。状态：待上传/接收中/处理中/已处理/需补充。密码错误只重新提交密码，不重传文件；不支持版式提示重新导出；平台不符提示选择正确材料；无权查看内部堆栈或他人文件信息。

刷新或断网后能查询已提交状态，避免重复入库。可替换错误文件，旧材料保留受控来源并标记未采用。完成提交不显示报告入口。

### H-04 兼容和交互

在公司确定的 Android/iOS 微信浏览器及系统浏览器真机测试选文件、后台切换、断网恢复、重复点击、失效会话。建议一期按 375–430 CSS px 手机宽度验收；文件上传失败保留可安全重用的表单状态，密码不写 localStorage。

## 5. 例外规则

- 缺一个平台：默认待补件；审核主管可以授权生成单平台报告并写原因，报告明确缺少平台，补齐后生成新版本。
- 姓名/证件冲突：阻断合并，人工处理归属，不向客户展示另一份材料的个人信息。
- 同一业务并发补件：创建不可变材料修订号；生成任务绑定修订号，过期任务不能抢占最新报告。
- 校验失败：不出“成功报告”，允许后台诊断和补件；不能跳过失败行凑齐总额。
- 场景未识别：可生成报告，视为规则覆盖边界，不作为解析失败。
- 同期跨文件重叠：一期用替换策略；未来多文件合并必须单独设计事件去重与期间并集。

## 6. 后续可选（P1）

全量 PDF/Excel 导出、机构词库维护界面、人工分类修订、同平台多账期合并、更多账单版本/OCR、管理统计。当前打印能力不算全量导出交付。若公司审批流程必须留档导出，应在估时前升为 P0，并增加下载权限、水印、审计和数据有效期要求。
